系统总体架构

星衍 LifeVerse 采用「前端沉浸式推演画布 + 规则/模型混合推理引擎 + RAG 知识底座」三层架构。交互原型与轻量算法（退休时钟、星图涟漪、向量匹配）在浏览器端 Canvas/JS 实时运行；重推理（路径推演、历史投影、报告生成）走后端 RAG + 规则引擎。本技术文档聚焦 已落地、可复算 的前端算法与数据模型。

① 交互表现层（前端）

  • Canvas 2D 星网背景
  • 混沌星云 / 双生时空 / 星图 / 光阴探针 Demo
  • Web Audio 音效引擎
  • 断代史报告渲染
→

② 推演引擎层（规则 + 轻模型）

  • 退休时钟（确定性政策算法）
  • 星图 BFS 涟漪 + 阻尼/反弹
  • 结构相似度向量匹配
  • 沙盘路径概率矩阵
→

③ 知识底座层（RAG）

  • 历史人物库 / 现代行业库
  • 未来趋势库 / 政策法规库
  • 关系传导规则库
  • 向量检索 + 可溯源引用
设计原则：「软推演建立想象力，硬计算建立信任感」。退休时钟等与政策强绑定的模块用 100% 确定性算法（可被任何人复算验证）；路径/关系/历史投影用 概率 + 可溯源规则，每条结论可追到知识库记录。
用户手势/输入→ 特征提取（Module 1）→ 镜像/历史匹配（Module 2/3）→ 路径推演（Module 4）→ 沙盘（Module 5）→ 退休时钟（Module 7）→ 星图涟漪（Module 8）→ 断代史报告（Module 6）

模块7 · 个人退休时间预测（退休时钟）

本模块是产品最「硬」的功能——政策白纸黑字、算法完全确定、结果可被任何人验证。算法严格对齐《关于实施渐进式延迟法定退休年龄的决定》（2024-09-13 通过，2025-01-01 施行）。以下实现已在 life-trajectory-prd.html 中以真实 JS 落地，并经 Node 复算验证。

核心算法（与 PRD 实现逐行对应）
// 1) 延迟月数：按出生年月所在「延迟档位」计算
function delayMonths(type, by, bm){
  var elapsed;
  if      (type==='male')     { elapsed=monthsFrom(1965,1,by,bm); return Math.min(36, Math.floor(elapsed/4)+1); }
  else if (type==='female55') { elapsed=monthsFrom(1970,1,by,bm); return Math.min(36, Math.floor(elapsed/4)+1); }
  else                      { elapsed=monthsFrom(1975,1,by,bm); return Math.min(60, Math.floor(elapsed/2)+1); }
}

// 2) 最低缴费年限：2029 及以前 15 年；2030 起每年 +0.5，封顶 20
function minPayYears(retireYear){
  if(retireYear<=2029) return 15;
  return Math.min(20, 15 + (retireYear-2029)*0.5);
}

// 3) 法定退休月序 = 出生月序 + 原法定年龄×12 + 延迟月数
statutoryIdx = birthIdx + baseAge*12 + dm;

// 4) 弹性钳制：提前不得低于原法定年龄；延迟最多 +36 月
earliestIdx = Math.max(statutoryIdx - 36, birthIdx + baseAge*12);
actualIdx   = clamp(statutoryIdx + flex, earliestIdx, statutoryIdx + 36);

// 5) 计发月数查表（FAFA）：50→195 / 55→170 / 60→139 / 63→117 …

模块8 · 人生星图涟漪传导引擎（BFS）

将家庭/职场关系建模为一张带权有向（无向存储）图，任一星体的状态事件沿引力网做广度优先传播（BFS），逐层计算受影响星体的参数变化，并以 Canvas 涟漪动画逐圈呈现。这是 v2.0 的灵魂模块，回答「中国人的重大人生决策从来不是一个人的事」。

图数据模型

节点（11 个，3 圈层 tier）：

tier角色颜色半径
0（中心）我#4f46e516
1（核心家庭）配偶 / 子女 / 父亲 / 母亲#d977069–11
2（协作圈）直属上级 / 核心同事 / 行业导师#0ea5e98
3（同代人星云）同代人 A / B / C#94a3b86

引力线（14 条）：每条 [src, dst, strength, resistance]

  • strength ∈ (0,1]：关系强度（影响传导的乘性系数）
  • resistance ∈ [0,1]：v2.1 新增关系阻尼系数（高阻尼 → 反弹波）

示例：['me','father',0.7,0.70] 表示「我↔父亲」强度 0.7、阻尼 0.70（代际价值观冲突高摩擦）；['me','spouse',0.9,0.30] 表示配偶强度高、阻尼低。

传播算法（castRipple）
const DECAY = [1, 0.7, 0.4, 0.15];   // 第0/1/2/3 圈衰减系数

function castRipple(sourceId, eventName, baseImpact){
  queue = [{id:sourceId, depth:0, impact:baseImpact}]; visited={sourceId:true};
  while(queue.length){
    cur = queue.shift();
    for(lk of links){
      nb = neighbor(lk, cur.id);
      if(!nb || visited[nb]) continue;
      strength   = lk[2];
      resistance = lk[3] || 0;
      nextImpact = cur.impact * strength * (DECAY[cur.depth+1] || 0.1);
      if(Math.abs(nextImpact) < 0.05) continue;   // 低于阈值截断
      visited[nb] = true;
      queue.push({id:nb, depth:cur.depth+1, impact:nextImpact});
      results.push({from:cur.id, to:nb, depth:cur.depth+1, impact:nextImpact, resistance});
    }
  }
  // 逐条输出动画 + 日志；resistance≥0.5 触发反弹波（见 05 节）
}
复杂度：图规模极小（|V|=11, |E|=14），BFS 为 O(|V|+|E|)=O(25)，单次推演 < 1ms。传播结果按 depth 排序后，以 idx*420ms 的节奏逐圈触发涟漪动画，形成「看得见、传得开、算得清」的心流。
效果节点文案映射（describeEffect）

每个被传导星体根据角色给出可解释的业务含义，而非抽象数字——这是「严肃决策价值」的体现：

星体传导后参数含义
配偶家庭现金流承压节点前移，「稳定优先」权重上调
子女教育预算曲线重算，兴趣班投入弹性区间收窄
父亲/母亲养老支持金 / 照护时间分配重排

同代人镜像人群路径样本 / 岗位竞争密度更新

关系传导规则库

BFS 中的 strength / resistance / 文案 来自「关系传导规则库」。首期 200 条由家庭财务规划师 + 社会学研究者联合编写，中期用镜像人群真实路径数据回归拟合扩充至 2000 条。

规则 Schema
// 单条规则结构
{
  id:            "R0001",
  eventType:     "职业变动",          // 婚育/购房/赡养/教育/职业变动/退休安排（6 大类）
  sourceRole:    "me",                 // 事件施加方角色
  targetRelation:"spouse",              // 受影响方关系
  transferFn:    "impact * 0.9 * DECAY[d]", // 传导函数（公式）
  decay:         0.7,                   // 该关系圈层衰减系数
  resistance:    0.30,                  // 阻尼系数
  confidence:    0.86,                  // 置信度
  source:        "专家评审 v1"           // 来源（人工/回归拟合）
}
首期规模 vs 中期目标：首期 200 条人工编写 + 双专家评审中期 2000 条（18 个月内）镜像人群数据回归拟合
评审备注：当前 PRD 原型中 strength/resistance 以常量数组内联（links 表），未接规则库表。生产化时须将 links 的 [strength, resistance] 改为查表 R[eventType][sourceRole][targetRelation]，以支持按事件类型动态选规则——这是 v2.1 之后的工程化待办。

关系阻尼与引力波反弹（Resistance & Echo Wave）

v2.0 的涟漪假设「影响沿引力线顺畅扩散」，但真实家庭系统里大量影响会被关系阻力消耗、甚至反弹。v2.1 给每条引力线加 Resistance 阻尼系数，让「家庭内部决策摩擦」变得可被看见、可被量化。

反弹波触发与摩擦度
// 在 BFS 结果逐条输出时：
if(r.resistance >= 0.5){
  friction = "⚠ 反弹波：家庭决策摩擦度 +" + (r.resistance*100).toFixed(0) + "%";
  ripples.push({ x, y, r, max:70, alpha:0.5, echo:true });  // 红色 Echo Wave
  LTASound.echo();                                      // 80Hz 锯齿摩擦声
}
阻尼系数 r传导表现视觉
r < 0.5影响正常衰减传播紫色涟漪
r ≥ 0.5触发反弹波，写入摩擦度增量红色 Echo Wave + 「家庭决策摩擦度 +X%」
⚠ 一致性审查发现（重要）：PRD 文本/MD 中描述的能量损耗模型 实际传导量 = 期望传导量 × (1 − r × 0.6) 与 life-trajectory-prd.html 当前实现不完全一致。当前实现：① 仅以 resistance≥0.5 触发红色反弹波动画 + 摩擦度日志；② 未在数学上用 (1−r×0.6) 衰减 nextImpact。即「反弹」目前是可视化 + 日志层，尚未真实削减传导强度。建议在 castRipple 中加入：
// 建议修复补丁（使 MD 描述与实现一致）
if(resistance >= 0.5) nextImpact *= (1 - resistance*0.6);  // 高阻尼损耗 30%~60% 能量

摩擦度为累积量：同一关系多次触发反弹持续累加，超阈值（如 60%）时断代史报告标注「该关系当前处于高摩擦状态，重大决策建议优先线下沟通」。阻尼系数首期按关系类型预置（我↔父母 0.70 / 我↔配偶 0.30），后续可由用户在星图上长按引力线手动微调。

结构相似度向量矩阵（Structural Vector Matrix）

正面回答「为什么我是后端开发，却匹配成唐朝漕运官，而不是宋朝修塔工？」——系统对每个现代职业困境与每个古代普通职业各抽取一个三维结构向量，用余弦相似度而非「职业名称相似度」做匹配，使历史投影可被解释、可被质疑、可被复算。

三维结构向量定义
维度含义取值语义
v₁ 系统网络脆弱性所处系统在冲击下的连锁崩塌风险高 = 牵一发动全身
v₂ 替代技术出现速度被新技术替代的速率高 = 技能贬值快
v₃ 官僚体制锁死程度制度僵化对个体选择的约束高 = 上升通道窄

$$ \text{sim}(q, v) = \dfrac{q \cdot v}{|q|\,|v|} = \dfrac{\sum_i q_i v_i}{\sqrt{\sum_i q_i^2}\,\sqrt{\sum_i v_i^2}} $$

其中 q 为当前用户经特征提取（Module 1）得到的「现代结构向量」；v 为候选古代职业向量。取 sim 最高者优先映射。

可验证算例（来自 PRD/MD 给定古代向量）
古代职业向量 [v₁, v₂, v₃]余弦相似度
唐朝漕运检修官[0.80, 0.75, 0.30]≈ 0.985（最高，优先映射）
明朝工部匠师[0.70, 0.60, 0.20]≈ 0.95
宋朝市舶书吏[0.55, 0.88, 0.45]≈ 0.94
可解释性：后端开发的核心困境（系统耦合脆弱、技术迭代快、科层晋升受限）与唐朝漕运检修官在三维结构上最接近，故优先投影——而非名字听起来像「修塔工」的宋朝岗位。用户可要求查看每个维度的数值对比，实现「算法透明」。

模块1 · 混沌星云注入（创世 Data Injection）

用「星体坍缩」物理手势取代传统表单：拖入简历/资料 → 星云坍缩 → 中心主星「我」成型；缺失字段以漂浮「引力微粒」呈现，点击/拖拽注入。

状态机与填充模型
  • 粒子系统：140 个粒子，自由漂移（边界反弹），requestAnimationFrame 驱动。
  • 坍缩态：点击注入后 condenseT 从 0 线性增至 1（每帧 +0.004），粒子向中心 (cx,cy) 收敛，速度 min(d, 2.4×condenseT)。
  • 主星成型：condenseT≥1 时主星「我」凝聚，完成度 fill 置为 72%，并生成 3 颗引力微粒（年龄 / 行业 / 困境）。
  • 微粒注入：每注入 1 个缺失字段 fill += 9%，进度条与特征卡实时更新；fill≥100% 时提示「主星体凝聚完成 ✦」。
字段→特征映射：fill 达 72% 即解锁特征卡（如 硬技能=Java后端/微服务、人生阶段=深耕期后半、生态位=可替代中层），无需等 100%，保证探索流畅。

模块3 · 双生时空剪影（跨时空共振）

用「多模态视觉隐喻」替代传统对比表：现代蓝轨（科技星轨 #0ea5e9）与古代金石轨（#8a6d3b）并列，悬停左侧现代节点触发「跨时空共振」光束 + 竹简风词条。

交互技术
  • 双轨：mNodes（现代）/ aNodes（古代）各 3 节点，纵向等距排布，中轴虚线分隔。
  • 共振光束：悬停时以二次贝塞尔 quadraticCurveTo(mx, my-40, a.x, a.y) 绘制琥珀色光束，光束上有一颗沿曲线运动的粒子（beamT 动画）。
  • 词条：3 组配对（技能贬值/技艺贬值、转型成本/学艺成本、周期下行/漕运缩减），点击 / 悬停切换竹简文案。
